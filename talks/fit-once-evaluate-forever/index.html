A use case: FINUFFT

flatironinstitute / finufft
The nonuniform FFT: the same Fourier coefficients as the DFT, for points that land anywhere, in \(\mathcal{O}(\sigma^d N\log N + M|\log\varepsilon|^d)\) instead of \(\mathcal{O}(MN)\).
\[ f_k=\sum_{j=1}^{M} c_j\,e^{\,ikx_j}, \qquad -\tfrac{N}{2}\le k<\tfrac{N}{2} \]
Used for MRI reconstruction, cryo-EM, the first image of a black hole.

The kernel: prolate spheroidal, order 0

\[ \int_{-1}^{1} e^{\,i c z t}\,\psi_0(t)\,dt = \lambda_0\,\psi_0(z), \qquad z\in[-1,1] \]
\(c\): time-bandwidth product · \(\lambda_0\): largest eigenvalue
\(\psi_0\) is the eigenfunction of the finite Fourier transform with the largest eigenvalue: among all band-limited functions it packs the largest fraction \(\lambda_0\) of its \(L^2\) energy into \([-1,1]\).
\[ \psi_0 = \arg\max_{\psi}\;\frac{\int_{-1}^{1}|\psi|^2} {\int_{-\infty}^{\infty}|\psi|^2} \quad\text{subject to}\quad \widehat\psi \text{ band-limited to } [-c,c] \]
Maximal concentration means minimal spill outside the kernel support, and that spill is the spreading error. The kernel is \(\varphi(x)=\psi_0(2x/w)\). Provably optimal. Genuinely expensive.

The recipe

  1. Approximate the expensive \(f\) with polynomials
  2. Evaluate the polynomials instead — a handful of fused multiply-adds
  3. Pay once, at fit time
The cost per call becomes flat, independent of how expensive \(f\) was.

Why Chebyshev nodes

  • Exponential convergence — error \(\sim \rho^{-n}\) for \(f\) analytic in a Bernstein ellipse of parameter \(\rho\)
  • Well-conditioned — the Lebesgue constant is 2.2 at degree 7, so a panel fit is within \(3.2\times\) of the best polynomial of that degree
  • Cheap to refine — low degree per panel, and the nodes of a panel are the nodes of its parent, rescaled
The classical reference is Trefethen, Approximation Theory and Approximation Practice, SIAM.

The case study

Hankel functions of the first kind, \(H_0^{(1)}(x)\) and \(H_1^{(1)}(x)\), for all \(x>0\).
\[ H_n^{(1)}(x) = J_n(x) + i\,Y_n(x) \]
The 2-D Helmholtz Green's function. The kernel of every 2-D fast multipole method, every scattering solver, every boundary integral code in the plane.
The reference implementation is hank103.f — Rokhlin and Gimbutas, Fortran, hand-tuned over thirty years. 93 ns per evaluation.

Which error, and where

a tolerance is a norm, not a number
tolerancerequestat a zero
absolute\(|p-f|\le \varepsilon\)attainable
max-normalised\(|p-f|\le \varepsilon\max|f|\)attainable
pointwise relative\(|p-f|\le \varepsilon\,|f(x)|\)unattainable
\[ \kappa(x)=\left|\frac{x\,f'(x)}{f(x)}\right| \]
relative condition number of evaluating \(f\) · unbounded at a zero, whatever evaluates it
Correct digits where the value is zero is not a hard fit. It is an ill-posed request, and every table in this talk therefore reports \(\max|p-f|/\max|f|\).

Two different reasons

Low \(x\) — a logarithmic branch point at the origin
\[ Y_0(x) = \frac{2}{\pi}\Big(\ln\tfrac{x}{2}+\gamma\Big)J_0(x) + \frac{2}{\pi} \sum_{k\ge1}\frac{(-1)^{k+1}H_k}{(k!)^2}\Big(\tfrac{x}{2}\Big)^{2k} \]

The cure is arithmetic, not a better fitter

Do the analysis first, and fit only what is left.
  1. Split the domain at the features
  2. Transform each regime so the remainder is polynomial-friendly
  3. Fit the remainder
  4. Add the analytic part back as a vectorised fixup
Nothing here is specific to Hankel functions.

High \(x\): do not fit at all

A batch is not a loop over scalars

measured
Unsorted mixed batch, before any fusing:
  • a range-partition sweep over the input
  • a gather into five heap vectors, per range
  • the full five-stage treeweave pipeline, per range
  • a separate fixup sweep over four output arrays
  • a scatter back
Eight heap allocations per call. 37.1 ns per evaluation, against 4.6 ns pre-sorted. The gap is entirely data movement.

One sort, fused fixups

treeweave::stages
The low-level interface, FFTW/FINUFFT style.
  • One combined-key counting sort over both fits and the asymptotic bucket the range id and the leaf id sort together, so one pass puts every point next to the points that need the same code path AND the same coefficients
  • Per-run dispatch, with the regime's fixup fused into the evaluation kernel
  • Persistent per-thread scratch — zero allocations in steady state
The log and the sincos now happen while the panel values are still in registers.

The recipe, once more

For a smooth function on a bounded domain, fitting is a solved problem: adaptive Chebyshev panels, a few nanoseconds per point, three lines of code.
For everything else, do the arithmetic first.
Split at the features. Transform each regime. Fit the remainder. Fuse the fixup back into the batch.
